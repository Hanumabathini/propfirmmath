# PropFirmMath membership build specification
Status: approved requirements; implementation and release gates pending. No live charges authorized.

## Entitlements
Free: 1 active account, basic journal, cloud saving and basic target/consistency tracking.
Pro: 10 active accounts maximum, premium command center, advanced journal, bulk entry, account groups, risk center, payout management, calendar, expenses, analytics, simulator, CSV and reports.
Elite: 25 active accounts maximum, Pro features plus consolidated financial reports, deeper portfolio risk and priority support.
Limits apply across firms; firm restrictions supersede plan capacity. Independent account IDs and versioned rules. Archive records without consuming active slots; downgrades preserve history and restrict editing to selected allowed active accounts. Enforce atomically on server including concurrent requests. Public calculators and directory remain accessible.

## Regional billing
Research country is freely selectable and never authorizes billing discounts. Billing country is independently assigned by server from declared residence, billing address and available verified payment-provider signals. IP country is a risk signal only, not proof of residence; VPN or travel is not automatic grounds for rejection. No GPS requirement. Mismatches require verification or a supported standard-price offer; do not silently change prices. Permanent relocation reviewed. Existing subscriptions retain contracted terms unless lawful disclosed change.
Store immutable country/currency/interval Stripe price mappings on server. Do not accept client-supplied amounts or arbitrary price IDs. Confirm verified billing country and quote before checkout, recheck provider country after checkout, and hold entitlement on unresolved mismatch. Signed idempotent webhooks establish entitlements, reconcile changes and refunds. Verify applicable taxes, supported countries, recurring payment methods and provider terms before offering checkout.

## Architecture and scope
Use Cloudflare Pages for production and Workers for privileged APIs; retain Vercel preview until migration is verified. Use Supabase Auth/Postgres, RLS and server-only privileged keys; Stripe test mode only until release approval. Email verification, Google login, password recovery, per-user data isolation, export/deletion, durable autosave with conflict recovery. Manual daily P/L and CSV imports; broker and prop-firm synchronization deferred. Premium dark/light responsive workspace, accessible keyboard-friendly spreadsheet, no fake live data. Track net realized cash separately from simulated trading P/L.

## Release gates
Test account limit races, cross-user access, tampered checkout price, VPN/travel/mismatched billing, webhook replay, downgrade preservation, autosave failures, restore backups, browser/mobile accessibility, calculation boundaries and official rule version provenance. Zero known critical/high severity defects before charging. No paid infrastructure upgrades or live billing activation without owner authorization.
Budget planning: Cloudflare Pages free tier, Workers free tier or paid if needed, Supabase Pro $25/mo, domain and optional email/monitoring; target $26–65/mo early commercial operation before transaction fees, taxes, professional reviews and labor. Initial reserve $150; not a binding quote. Build/test with available free development tiers where permitted.

## Mandatory security acceptance criteria
- Separate PropFirmMath database and environments; no Parkday data or credentials reused. MFA for owners and administrators; least privilege, protected branches, review and secret scanning. No public service-role keys, Stripe secrets or database passwords; rotate exposed credentials promptly.
- Enable RLS on every exposed user table, explicit ownership policies and minimal grants. Do not trust user-editable metadata for entitlements. Atomic database-enforced account limits (1/10/25); verify ownership on every read/write/export/archive. Deny anonymous private-data access. Test direct API access and concurrent requests.
- Use verified authentication, secure session handling, MFA support, account recovery, rate limits and server-verified Turnstile on abuse-prone flows. Prevent account enumeration and credential stuffing. Reauthentication for sensitive operations.
- Cloudflare HTTPS, HSTS after domain validation, restrictive CSP, frame protection, nosniff and referrer policy; scoped CORS, CSRF protection where cookie authentication applies, input validation and safe output encoding. Protect CSV exports from formula injection. Enforce origin-side authorization even when Cloudflare is bypassed.
- Stripe-hosted checkout only; never store card numbers or CVV. Verify raw-body webhook signatures, replay protection, idempotency and subscription state; server-approved regional prices only. No client-side privilege escalation or fake billing success.
- Minimize personal data; never request prop-firm/broker credentials in manual-entry phase. Encrypt transport and managed storage; redact secrets, tokens and financial records from logs. Provide user export/deletion; separate audit records with restricted access and retention.
- Pin dependencies, scan vulnerabilities, isolate preview from production and use synthetic test records. No live secrets in preview. Use independent restore-tested backups, incident response and rollback playbooks, alerts for suspicious activity and spend limits.
- Release requires documented tests for cross-user access, privilege escalation, session abuse, XSS/CSRF/injection, webhook tampering, regional price bypass, account-limit races and backup recovery. Use OWASP ASVS as verification baseline. No known critical/high vulnerabilities before paid launch; independent review recommended. Controls are requirements until implemented and verified.
